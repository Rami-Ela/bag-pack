### ❓ Question de Claude · _20:03:56_

**Auth — Which approach do you want for authentication?**

- **Hand-rolled (Recommended)** : Password hashed with node:crypto scrypt (no dependency), Session table in the DB, httpOnly cookie, proxy.ts to redirect to /login. About 200 lines, fully under your control, no extra dependency.
- **Better Auth** : Dedicated library with a Prisma adapter and built-in email/password. Less code to write, but it imposes its own tables (session, account, verification) and adds a dependency.
- **Auth.js (NextAuth)** : Credentials provider. Not a good fit for passwords: it requires JWTs, and the docs discourage using credentials. Not recommended.

**Prod migr. — How do you want to take over the prod data (user 'default-user')?**

- **CLI script (Recommended)** : A script `npm run user:claim -- <email> <password>` run once against the prod DATABASE_URL. It updates default-user's email and password hash. No secret in the repo.
- **Env var at signup** : The first signup whose email matches CLAIM_EMAIL takes over default-user. Nothing to run by hand, but it adds permanent logic to the app.
- **Fixed password in SQL** : The SQL migration sets a known temporary hash, and you change the password afterwards. Requires a password-change screen and puts a hash in the repo.
